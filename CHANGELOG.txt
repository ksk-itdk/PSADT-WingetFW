**Version 5.0.0 [14/10/2026]**
- Added WingetFW 5.0.0 on PSAppDeployToolkit 4.1.8 in Toolkit\WinGetFW5.0.0. The setup file is Invoke-AppDeployToolkit.exe instead of Deploy-Application.exe. WingetFW 4.0.8 stays in Toolkit\WinGetFW
- Changed the WingetFW functions (Install-WinGetFM, Get-WinGetVersionFM, Start-WinGetPackageFM, Resolve-WingetPath) into the extension module PSAppDeployToolkit.Extensions. The WingetFW logic is unchanged
- Changed the settings file from AppDeployToolkitExtensionsConfig.xml to PSAppDeployToolkit.Extensions\Config\WingetFW.psd1 (TlsCheck and VCRedistCheck, both $false in the package)
- Changed reboot exit codes (1641, 3010) so they are passed to Intune by default. -AllowRebootPassThru is removed; use -SuppressRebootPassThru to return 0 instead
- Changed error handling so an error no longer shows a dialog; -DeployMode NonInteractive is no longer needed in user mode
- Changed command line quoting: with Invoke-AppDeployToolkit.exe a double-quoted value with spaces stops with exit code 1 (4.0.8 returned 0). Use single quotes for values with spaces and for {GUID}
- Added exit code 60008 when PSAppDeployToolkit cannot start
- Added settings levels: policy (HKLM\SOFTWARE\Policies\WingetFW, from Intune or GPO), command line, local key (HKLM\SOFTWARE\WingetFW), config file, built-in default. Each setting and where it came from is logged
- Added the ADMX/ADML in the Policies folder for Intune (Import ADMX) and GPO
- Added the settings DefaultSilent (adds -silent when none of -silent, -interactive, -override is used; on by default), DefaultSource (install and upgrade), AllowedSources (other sources stop with 60001), Sources (REST sources added in Admin mode), Proxy and ProxyBypass (winget --proxy and WingetFW's own downloads; ProxyCommandLineOptions is enabled in Admin mode)
- Changed the config keys WingetFW_TlsCheck and WingetFW_VCRedistCheck to TlsCheck and VCRedistCheck; both can now also come from policy or the local key
- Changed the README into a short front page; the documentation is in the Docs folder (Getting started, Parameters, Configuration, Mod files, Signing mod files, Exit codes and logs, Upgrading Intune apps)
- Added mod files: PowerShell files with Pre, During, Post and Not sections that run around winget, per app (<ScriptRoot>\<source>\<id>.ps1) or for all apps (_WingetFW.ps1). $Settings in the app mod sets winget options per action (the command line beats it). A Pre section that returns $false skips the action with exit code 69002. Template: Mods\_Template.ps1
- Added the mod settings ScriptRoot (local folder, UNC share or Azure blob URL; default the package Mods folder), ScriptSyncMode (OnDemand, Mirror), UseCachedScriptsWhenOffline, AllowedScriptSources, RequireSignedScripts (Off, Signed, TrustedSigners) and TrustedSigners, also in the ADMX
- Added a load check for mod files: only function definitions and $Settings with fixed values at the top level; other files stop with 60001
- Updated Tools\Update-WingetFWIntuneApps.ps1 to 0.2.0 (BETA): converts Deploy-Application.exe to Invoke-AppDeployToolkit.exe, removes -AllowRebootPassThru, reports ServiceUI.exe in a command line as an error, uses the newest Toolkit\WinGetFW* folder as the target version and no longer warns about -Mode User without NonInteractive. Tools\WingetFW-ParameterMap.psd1 has the new settings ExeName, OldExeNames and SuppressRebootPassThru
- Updated the test suite (Invoke-WingetFWTestSuite.ps1 1.7.0, Invoke-WingetFWVmTest.ps1 1.2.0) to test 5.0.0 by default; -Package WinGetFW tests 4.0.8. Settings tests S01-S12, mod tests M01-M15 and conflicting-app tests C01-C04 added. Result for 5.0.0: 70 of 70 tests passed
- Updated README.md for 5.0.0; the 4.0.8 README is now README-4.0.8.md
- Added WingetFW.Core 1.2.0 in Source\WingetFW.Core (settings reader with the order Policy, command line, mod file, local key, config file, default; logging; WingetFW event log; state files; mod files). The package loads a copy from PSAppDeployToolkit.Extensions\WingetFW.Core
- Added CI on GitHub: PSScriptAnalyzer and Pester unit tests (Tests\Invoke-WingetFWCi.ps1, Tests\Unit) on every code change, the VM suite on a self-hosted runner (manual or release only) and a release workflow (Build\New-WingetFWRelease.ps1, zip, optional SignPath signing, GitHub Release from this file)
- Added WingetFW Console 0.2.0 (Console\Start-WingetFWConsole.ps1, PowerShell 7.4): search winget packages, show the manifest details and installers, build the install and uninstall commands with the WingetFW option rules, create the detection script from the newest template, and create the Win32 app in Intune (sign-in as the admin, .intunewin upload, detection script, return codes incl. 69002 as retry, requirements, group assignments). See Docs\Console.md
- Updated Tools\Update-WingetFWIntuneApps.ps1 to 0.3.0 (BETA): uses the Graph and upload functions of the WingetFW.Console module and needs PowerShell 7.4 or later

**Version 4.0.8 [11/10/2026]**
- Fixed an issue where User mode failed right after a user's first logon because Windows registers winget (App Installer) a few seconds late; WingetFW now requests the registration and retries for up to about 20 seconds
- Changed Install so a package that is already installed (winget 0x8A150061 or 0x8A15002B) is logged as already installed and returns exit code 0 instead of failing
- Added Tools\Update-WingetFWIntuneApps.ps1 (BETA, not fully tested, use at your own risk) to find all WingetFW apps in Intune, export them to a CSV with the converted command lines, and update the selected apps to the new WingetFW package. The parameter conversion from 3.x and 4.0.x is in Tools\WingetFW-ParameterMap.psd1
- Added new version of registryversionregex (v1.0.2) detection: the version is compared as a version again (9.10 is newer than 9.9) and non-digit parts of DisplayVersion are replaced by dots, so "v2.3-beta" is compared as 2.3
- Added new version of registryversionregex (v1.0.3) detection: versions with one number or no number are compared as x.0 and 0.0 instead of failing; before, the version of the previous app in the list could be used
- Added new version of wingetv (v2.0.2) detection: Admin/SYSTEM uses the newest App Installer folder, User mode retries for up to 20 seconds after first logon, the winget exit code is checked (errors are retried and then return exit code 1) and winget is stopped after 120 seconds
- Added a help header (synopsis, examples, version and release notes) to all detection scripts in Toolkit\Detection
